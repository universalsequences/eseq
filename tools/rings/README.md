# Rings port tooling

This folder holds the source and verification tooling for the `Synths/Rings`
factory instrument (`content/instruments/Synths/Rings`). That instrument's
`dsp.lisp` is **generated** from the files here, so edit these and then
regenerate:

```sh
EURORACK=/path/to/pichenettes/eurorack tools/rings/regenerate.sh
```

The script regenerates three things:

- the lookup tables in the instrument's `data/` folder, from `rings/resources.cc`;
- the generated Lisp sources, listed under Layout;
- the assembled `dsp.lisp`.

The port follows eurorack commit `f4cfa769`. On that commit, the output is
byte-identical to what is checked in.

## Layout

- `src/header.lisp`: the instrument's inputs and params.
- `src/voice.lisp`: the voice. It covers:
  - `rings.cc`, `cv_scaler.cc` and `strummer.h`: the 24-sample block clock, strum detection with the 10 ms inhibit, and the chord hysteresis;
  - model selection;
  - the effects routing, the limiter and the outputs.
- `lib/common.lisp`: stmlib primitives.
- `src/modal.lisp`: the 60-mode resonator, generated by `tools/gen_modal.py`.
- `src/fm.lisp`: the FM voice.
- `src/strings.lisp`: the plucker, the 8 strings and the sympathetic-string tuning. It is generated by `tools/gen_strings.py` from `tools/*.lisp.in`.
- `src/peace.lisp`: Disastrous Peace, generated by `tools/gen_peace.py`.
- `src/fx.lisp`: the reverb, plus the chorus and ensemble on shared delay lines.
- `src/tables.lisp`: chord, registration and formant tables, parsed from the sources by `tools/gen_tables.py`.
- `tools/assemble.py`: concatenates the above into `dsp.lisp`. `voice.lisp` wraps the scalar models in `(block-gate …)`, so only the selected one runs.

The modal, FM and Disastrous Peace models can be gated. The strings and
effects cannot, because they need delay memory, and a block-gate's whole
upstream cone must be scalar. For the same reason, controls feeding the gated
models are history sample-and-holds, not `latch`: an event latch may not feed
a block-gate.

## Verifying against the original

`ref/rref.cc` renders `rings::Part` (models 0–5) or `rings::StringSynthPart`
(models 6–11) at polyphony 1, driven the way the instrument drives them.
Build it with `EURORACK=… ref/build.sh`.

`ref/shim` holds test-only copies of stmlib's `Random`, `plucker.h` and
`string.cc`. They let the reference run with one of two noise sources:

- **Constant noise:** `RREF_U=<u>`, matched by `assemble.py --const-u`.
- **The port's own noise streams:** `RREF_NOISE=<file>`, recorded by `assemble.py --noise-out`.

The test scripts:

- `tools/rh.py` (`VoiceTest`) assembles the instrument and compares it with the reference.
- `tools/test_models.py` compares every model across settings, sweeps and retriggers, with constant noise.
- `tools/test_noise.py` compares the noise-excited models statistically against the reference's spread over seeds.
- `tools/test_robust.py` renders extreme settings at 44.1 and 96 kHz.
- `tools/presets.py` writes `Rings.presets` with loudness-matched levels. With `RINGS_DEMOS=<dir>` it also renders one demo WAV per preset.

Generated test instruments go to `$RINGS_WORK` (default `~/.cache/eseq-rings`).
