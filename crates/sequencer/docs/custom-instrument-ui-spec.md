# Custom Instrument Synth UI Spec

## Purpose

Custom DGenLisp instruments currently inherit a generic Synth tab UI: visible
parameters are listed as rows of label, number picker, and slider controls.

This spec adds an optional per-instrument `ui.lisp` file that lets instrument
authors arrange the Synth tab body with normal `eseqlisp` UI primitives while
using small parameter-binding helpers for the repetitive control wiring.

The goal is to make custom instruments feel native and intentionally designed
without requiring every instrument author to manually write parameter lookup,
value formatting, p-lock state, and host update commands.

## Design Goals

- Keep existing `eseqlisp` layout primitives: `h-stack`, `v-stack`, `box`,
  `tabs`, `label`, `number-picker`, `hslider`, etc.
- Add only the instrument-specific binding layer needed to render and edit DSP
  parameters.
- Make the common case terse:

```lisp
(params cutoff resonance drive gain)
```

- Let instrument authors progressively customize presentation:

```lisp
(param cutoff :as :knob :label "freq" :scale :log)
```

- Keep the app-owned Synth / Mod / Sources tabs outside the custom UI.
- Fall back to the current autogenerated parameter UI when `ui.lisp` is
  missing, invalid, or does not register a synth UI.
- Support multiple tracks using the same instrument. The custom UI must render
  against the selected track's instrument instance.

## Non-Goals For V1

- Replacing the existing layout/widget system.
- Letting custom instrument UI control the outer Synth / Mod / Sources tabs.
- Custom Mod or Sources tab layout.
- A full visual canvas/vector authoring language.
- Dynamic creation of new DSP parameters from `ui.lisp`.
- Changing DSP parameter truth from UI metadata. DSP metadata remains canonical.

## File Layout

Existing single-file instruments remain supported:

```text
instruments/minimoog.lisp
```

New folder-style instruments may use:

```text
instruments/minimoog/
  dsp.lisp
  ui.lisp
  presets.lisp      ; optional future format
```

Rules:

- `dsp.lisp` is the DGenLisp instrument source.
- `ui.lisp` is optional `eseqlisp` UI source for the Synth tab body.
- The folder name is the instrument identity unless overridden later by a
  manifest-level feature.
- The loader should continue supporting legacy `instruments/<name>.lisp`.
- If both `instruments/<name>.lisp` and `instruments/<name>/dsp.lisp` exist,
  the host should treat them as separate instruments unless an explicit
  migration rule is added.

## Instrument Discovery And Sidebar Display

The instrument browser/sidebar must discover both legacy single-file
instruments and folder-style instruments.

Supported discovery entries:

```text
instruments/foo.lisp
instruments/bar/dsp.lisp
```

Rules:

- `instruments/foo.lisp` appears as instrument `foo`.
- `instruments/bar/dsp.lisp` appears as instrument `bar`.
- `instruments/bar/ui.lisp` must not appear as a separate selectable item.
- `instruments/bar/presets.lisp` or `instruments/bar/*.presets` must not appear
  as separate selectable instruments.
- A folder is considered an instrument only if it contains `dsp.lisp`.
- Folders without `dsp.lisp` are ignored by the instrument picker.
- Hidden folders and hidden files are ignored.
- The sidebar should display a single flat instrument list for V1 unless a
  later browser design adds grouping.

If both forms exist:

```text
instruments/foo.lisp
instruments/foo/dsp.lisp
```

the sidebar must show two unambiguous entries. Suggested labels:

```text
foo
foo/
```

or, if the UI supports subtitles:

```text
foo        lisp file
foo        folder instrument
```

The selected instrument entry must carry a source kind and source path, not only
the display name:

```text
InstrumentSource
  name: "foo"
  kind: LegacyFile | Folder
  dsp_path: instruments/foo.lisp | instruments/foo/dsp.lisp
  ui_path: None | instruments/foo/ui.lisp
  preset_path: optional
```

This avoids ambiguous behavior when a legacy file and folder-style instrument
share the same base name.

## Host-Owned Outer UI

The app continues to own this structure:

```text
[synth] [mod] [sources]
```

The custom instrument UI only supplies the body rendered when the selected tab
is `synth`.

Conceptually:

```lisp
(tabs :items (list "synth" "mod" "sources") ...)

(if (= selected-tab "synth")
  (render-selected-instrument-synth-ui-or-fallback)
  ...)
```

Instrument authors must not define these top-level tabs in `ui.lisp`.

## Core Special Form

### `defsynth-ui`

Registers the custom Synth tab body for the instrument that owns the current
`ui.lisp` file.

Example:

```lisp
(defsynth-ui
  (h-stack :gap 1.2 :padding 1
    (params base_note shape formant detune_ce unison sync_amt alias)
    (params cutoff resonance filter_en keytrack drive gain)))
```

Rules:

- `defsynth-ui` takes one body expression.
- It may be invoked at most once per `ui.lisp` in V1.
- The instrument name is inferred from the folder being loaded.
- The body is evaluated/rendered in an implicit instrument instance context.
- That context is rebound by the host whenever a different track instance is
  selected.
- Top-level `def` helpers in `ui.lisp` are allowed and may be referenced by the
  body.

## Instrument Instance Context

Inside a `defsynth-ui` body, symbolic parameter references resolve against the
currently selected track's instrument descriptor and parameter defaults.

For a selected track, the context provides:

- instrument identity
- track index
- parameter descriptors from the DGenLisp manifest
- current default parameter values for that track
- selected step p-lock overlay state, if applicable
- host command functions for setting defaults or p-locks

The UI author does not pass the track explicitly.

## Parameter Reference Syntax

Parameter helpers use symbols, not strings:

```lisp
(param cutoff)
(params cutoff resonance drive)
```

Benefits:

- shorter authoring
- load-time validation
- better error messages
- easier future tooling and autocomplete

Validation errors should identify unknown parameters:

```text
ui.lisp: unknown parameter `cuttof`; did you mean `cutoff`?
```

## Core Parameter Helpers

### `param`

Renders one parameter control bound to the current instrument instance.

```lisp
(param cutoff)
```

Options:

```lisp
(param cutoff
  :as :knob
  :label "freq"
  :decimals 1
  :width 8
  :scale :log)
```

V1 supported `:as` values:

- `:slider` - label + number picker + horizontal slider
- `:knob` - compact knob-style control with label/value
- `:number` - label + number picker only
- `:toggle` - binary toggle/checkbox-style control
- `:select` - dropdown/select control
- `:hidden` - validates the param but renders nothing

If `:as` is omitted, the default is `:slider`.

Common options:

- `:label <string>` overrides the visible label
- `:decimals <int>` overrides numeric precision
- `:width <number>` presentation width hint
- `:unit <string>` presentation unit override
- `:scale :linear | :log` display/control scale hint
- `:min <number>` UI presentation clamp override
- `:max <number>` UI presentation clamp override
- `:step <number>` number-picker step override

Select options:

```lisp
(param shape
  :as :select
  :choices ((0 "sine") (1 "tri") (2 "saw") (3 "square")))
```

Rules:

- DSP manifest metadata remains canonical for actual parameter min, max,
  default, and unit.
- UI overrides affect display/control presentation only.
- Setting a parameter uses the same semantics as the existing generic Synth
  tab: if steps are selected, write p-locks; otherwise write the track default.

### `params`

Renders multiple parameter controls as a vertical stack.

```lisp
(params cutoff resonance drive gain)
```

Equivalent conceptually to:

```lisp
(v-stack :gap 0.25
  (param cutoff)
  (param resonance)
  (param drive)
  (param gain))
```

Group-level defaults:

```lisp
(params :as :knob
  cutoff resonance drive)
```

Per-parameter options:

```lisp
(params
  cutoff
  (resonance :as :knob :label "res")
  (drive :as :knob)
  (gain :as :number))
```

Rules:

- Group-level options apply to all child params unless overridden by a child.
- Child entries may be bare symbols or option lists.
- `params` should produce stable dimensions matching the existing Synth tab
  style where possible.

## Value Access Helpers

These helpers are for custom compound widgets and user-defined helpers.

### `param-value`

Returns the currently displayed value for a parameter in the active context.

```lisp
(param-value cutoff)
```

If selected steps contain a p-lock for the param, this returns the displayed
p-lock value. Otherwise it returns the track default.

### `set-param!`

Sets a parameter in the active context.

```lisp
(set-param! cutoff 4200)
```

Rules:

- If steps are selected, writes p-locks to selected steps.
- If no steps are selected, writes the track default.
- Values are clamped according to the DSP descriptor.

### `param-meta`

Returns a dictionary of descriptor metadata.

```lisp
(param-meta cutoff)
```

Suggested shape:

```lisp
(dict
  :name "cutoff"
  :min 60
  :max 12000
  :default 2400
  :unit "Hz"
  :hidden false)
```

### Future Helpers

These are not required for V1 but should be compatible with the design:

```lisp
(param-default cutoff)
(param-normalized cutoff)
(set-param-normalized! cutoff 0.5)
(param-plocked? cutoff)
(clear-param-plock! cutoff)
```

## User-Defined Helper Widgets

Instrument authors may define ordinary helper functions/macros in `ui.lisp`.
These are not core primitives.

Example:

```lisp
(def operator-panel (name &key coarse fine fixed level env)
  (v-stack :gap 0.45
    (h-stack :gap 0.5 :align :center
      (label name :font-size 12 :color :white :bg :transparent)
      (param fixed :as :toggle :label "fixed")
      (param level :as :knob :label "level"))

    (h-stack :gap 0.7
      (param coarse :as :knob :label "coarse")
      (param fine :as :knob :label "fine"))

    (adsr
      :attack (nth env 0)
      :decay (nth env 1)
      :sustain (nth env 2)
      :release (nth env 3))))
```

Core should not special-case helpers like `operator-panel`.

## Standard Library Helper Widgets

The host may ship reusable helpers built on top of `param`, `param-value`, and
`set-param!`.

Suggested first helpers:

```lisp
(adsr :attack amp_attack
      :decay amp_decay
      :sustain amp_susta
      :release amp_relea)
```

Optional positional shorthand:

```lisp
(adsr amp_attack amp_decay amp_susta amp_relea)
```

Other candidates:

- `filter-panel`
- `lfo-panel`
- `operator-envelope`
- `macro-knobs`

These helpers are library conveniences, not part of the minimal host contract.

## Complete Example

```lisp
;; instruments/mono_synth/ui.lisp

(defsynth-ui
  (h-stack :gap 1.2 :padding 1

    (v-stack :gap 0.45
      (label "oscillator" :font-size 11 :color :gray :bg :transparent)

      (h-stack :gap 0.8 :align :center
        (param shape :as :select
          :label "shape"
          :choices ((0 "sine") (1 "tri") (2 "saw") (3 "square")))

        (param morph :as :knob :label "morph" :decimals 2))

      (params :as :slider
        base_note
        detune_ce
        unison
        sync_amt
        alias))

    (v-stack :gap 0.45
      (label "amp" :font-size 11 :color :gray :bg :transparent)

      (adsr
        :attack amp_attack
        :decay amp_decay
        :sustain amp_susta
        :release amp_relea)

      (h-stack :gap 0.7
        (param gain :as :knob :label "gain")
        (param drive :as :knob :label "drive")))

    (v-stack :gap 0.45
      (label "filter" :font-size 11 :color :gray :bg :transparent)

      (h-stack :gap 0.7
        (param cutoff :as :knob :label "freq" :scale :log)
        (param resonance :as :knob :label "res"))

      (params
        (filter_en :as :toggle :label "env")
        (keytrack :as :slider :label "key")
        (drive :as :slider)))

    (v-stack :gap 0.45
      (label "texture" :font-size 11 :color :gray :bg :transparent)

      (params
        (noise_lev :as :knob :label "noise")
        (phase_dis :as :knob :label "phase")
        (comb_amt :as :knob :label "comb")
        (comb_time :as :number :label "time")
        (vowel_amt :as :slider :label "vowel")))))
```

## Runtime Loading Flow

For folder-style instruments:

1. Read `instruments/<name>/dsp.lisp`.
2. Compile/load it with the existing DGenLisp instrument path.
3. Parse the manifest and parameter descriptors.
4. If `instruments/<name>/ui.lisp` exists:
   - evaluate it in an `eseqlisp` environment with custom instrument UI
     bindings installed
   - validate symbolic parameter references against the manifest
   - register the `defsynth-ui` body for `<name>`
5. When the Synth tab renders for a selected track:
   - if the track's instrument has a registered custom synth UI, render it with
     the selected track bound as the instrument context
   - otherwise render the autogenerated parameter grid

## Error Handling

UI errors must not break audio or prevent instrument loading.

Recommended behavior:

- `dsp.lisp` compile errors block loading the instrument, same as today.
- `ui.lisp` parse/eval errors produce a visible UI error and fall back to the
  autogenerated Synth tab.
- Unknown parameter references produce a visible UI error and fall back.
- Unsupported widget modes in `:as` produce a visible UI error and fall back.

The fallback should remain available even while editing `ui.lisp`.

## Compatibility

Legacy instruments:

```text
instruments/foo.lisp
```

continue to load and render with the autogenerated Synth tab.

Folder instruments without `ui.lisp`:

```text
instruments/foo/dsp.lisp
```

load and render with the autogenerated Synth tab.

Folder instruments with `ui.lisp`:

```text
instruments/foo/dsp.lisp
instruments/foo/ui.lisp
```

load DSP from `dsp.lisp` and render the Synth tab body from `ui.lisp`.

## Implementation Notes

The minimal implementation can be layered on existing `ui/effects.lisp`
patterns:

- reuse the current generic parameter row behavior for `param :as :slider`
- implement `params` as a macro expanding to a `v-stack`
- store the registered `defsynth-ui` body per instrument
- add host functions for current instrument param read/write by symbolic name
- inject an instrument context before rendering the selected track's custom UI

V1 does not need a perfect native knob. `:knob` can initially render as a
compact parameter control and later be replaced by a real knob widget without
changing authored `ui.lisp` files.
